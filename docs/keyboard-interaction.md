# 顶部固定键盘交互 · 0.9.9

2026-10-01 · 当前基线 [v2.7](product-blueprint.md)。

用户实测反馈：底部入口随系统键盘升降的衔接不够流畅。本版把键盘／收起按钮固定在右上角，输入条固定在顶部按钮下方。两个按钮同为 48 × 48 CSS px，顶部及侧边留至少 14 px；输入条位于 y=78 px（安全区域较大时向下避让），高 88 px、左右至少 16 px、最大宽 560 px。

输入条仅做淡入淡出，键盘图标与收起箭头在原位交叉淡化。布局不使用视口高度计算 top，不做位移、缩放或背景展开。下拉箭头仍可收起，但手势过程不再牵引任何控件。空白区域收起、同步 focus、IME、听写与退格逻辑沿用现有实现。失活按钮独立 inert，隐藏输入区域不进入焦点导航。

验收重点：完整视口、键盘占屏后的短视口以及恢复视口时，切换按钮尺寸和坐标一致，输入条 top 一致；Safari 系统可见区域偏移和安全区域仍需手机安装验证。本轮结果见 [验证记录](validation.md)。

## 设计判断与截图审查

1. **保留底部入口。** 原界面的中心胶囊容易被左右手拇指够到，也不占独立工具栏。新版把触摸范围由 104 × 48 增加到 120 × 52 CSS px。
2. **合并三个视觉层次。** 原界面将文本框、同步提示、收起把手分开，图标还执行独立变形。新版让胶囊背景连续展开为一个 88 px 高的输入条，输入框与收起按钮并排，同步提示收进同一面板。
3. **让退出动作就近完成。** 箭头支持点击与向下轻拉；未到阈值时回到原位。点空白触控区也是关闭入口，方便左手使用。下拉只发生在箭头按钮内，输入框的原生选字与中文候选不受影响。

## 操作与动效

| 动作 | 反馈 |
| --- | --- |
| 轻点底部键盘 | 同一次用户事件立即聚焦文本框；同一背景面由胶囊扩展成输入条 |
| 展开 | 300 ms 单一进度，先淡出入口图标，再显现输入内容；无弹跳、图标变形或旋转 |
| 轻点箭头／空白区 | 立即失焦，面板在 240 ms 内回收；不向 Mac 发出鼠标点击 |
| 下拉箭头 | 面板跟随 55% 的手指位移，最大 40 px；44 px 下拉或至少 20 px 的快速下甩后松手收起 |
| 短拖、横滑、向上滑、触控取消 | 面板归位，输入状态保留；不补发点击 |
| 快速反向操作 | 从当前呈现位置继续，根据剩余距离缩短时长 |
| 减少动态效果 | 直接切换终态，关闭下拉归位动画 |
| 外接键盘 Escape | 关闭输入条并把焦点交回键盘入口；输入法组合期间不截获 |

软件键盘的曲线和时长由操作系统决定。网页只动画面板的形状和内容，位置逐帧跟随真实可见视口，不额外给视口位置叠加缓动。浏览器的 [VisualViewport API](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) 提供键盘占屏后的可见高度及偏移；实际观察到大幅压缩后才启用键盘关闭检测，避免普通地址栏变化导致误收起。旋转或缩放时重置检测基准。

焦点必须在轻点回调里同步设置，不能为了等待动画而延迟；用户激活的时间边界见 [WebKit User Activation API](https://webkit.org/blog/13862/the-user-activation-api/)。本次保留原有实时文本、IME、听写、退格及旧主机粘贴路径。

## 实现与验收

- `Web/src/keyboard-transition.ts`：可反向、按剩余行程计时的面板进度。
- `Web/src/keyboard-pull.ts`：专用下拉识别与误滑取消。
- `Web/src/keyboard-viewport.ts`：可见区域变化及系统收起判断。
- `Web/src/app.ts`、`index.html`、`style.css`：同步 focus、指针捕获、焦点导航与一体布局。

自动化与安装包结果记录在 [验证记录](validation.md)。手机验收重点为连续开合、Safari 地址栏展开／收起、横竖屏、中文候选和听写结束、系统自带收键盘按钮，以及左右手持握时的按钮可达性。
