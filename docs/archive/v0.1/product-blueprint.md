# SofaPad：客厅触控板 MVP 产品蓝图

> 版本：v1.3 · 2026-09-09
> 状态：0.1.0 开发预览已实现、构建并完成本机自动验证；iPhone Safari、实际鼠标事件和电视体验尚未验收。
> 最新架构：Mac 原生菜单栏 App + iPhone 网页，替代此前的双原生方案。
> 本地网页由 Mac App 内置。首版提供默认关闭、需用户主动接受的 HTTP/WS 家庭模式；HTTPS/WSS 尚未实现。实测与能力调整见 [决策](decisions.md) 和 [验证记录](validation.md)。

## 1. 产品定义

让 iPhone 成为连接电视的 Mac mini 的无线触控板。用户看着电视，通过手机移动指针、点击、右键和滚动，打开视频应用、筛选内容、播放视频，使用 Mac 自带的辅助功能键盘输入少量搜索词。

### 已确认的决策

| 编号 | 决策 |
| --- | --- |
| D-01 | Mac 安装原生 App；iPhone 改为网页，免除手机安装与签名维护 |
| D-02 | Mac 提供系统支持的登录启动开关；用户启用后在登录会话内运行，控制服务沿用用户之前的启用选择 |
| D-03 | 手机发起配对和连接，认证成功后控制鼠标 |
| D-04 | 只实现单指移动、轻点、双击、双指轻点、双指横纵滚动 |
| D-05 | 手机不做键盘；文字输入交给 Mac 辅助功能键盘 |
| D-06 | 家庭电视影音场景；公开源码，暂不发布 App Store |
| D-07 | 单仓库同时包含 Mac App 与网页源码；最终用户只安装一个内置网页的 Mac App |

手机端原先的“键鼠切换区域”取消，右上角改为连接／设置入口。项目名称为 **SofaPad**（Sofa + Trackpad），仓库名为 `sofapad`：坐在沙发上，通过手机浏览器操作 Mac。

## 2. GitHub Pages 与网页托管决策

### 2.1 可以发布网页，但托管与连接是两件事

GitHub Pages 可以发布触控板所需的 HTML、CSS、JavaScript。它只负责静态页面，不运行本产品的常驻 WebSocket 服务，也不能替代 Mac 上执行鼠标事件的软件。[GitHub：创建 Pages 站点](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

线上方案的路径是：手机从 Pages 加载页面，页面再直接连接家中的 Mac。操作数据不必经过 GitHub，但本地连接要满足浏览器的安全策略。

- HTTPS 页面直接连接普通 `ws://192.168.x.x:端口` 涉及混合内容限制，不能作为 iPhone Safari 的可靠基线。
- 需要采用浏览器接受的 `wss://` 连接，处理证书信任、主机名与局域网解析。
- Pages 的 HTTPS 证书只保护 Pages 网站，不会自动保护家中 Mac 的服务。
- 浏览器 JavaScript 不能像原生客户端那样接管 TLS 校验并自行接受指定自签名证书。
- 单独配置 CORS 无法解决混合内容、证书或浏览器局域网访问策略问题。

因此，“页面能在 Pages 打开”不等于“能控制 Mac”。具体可用性必须在用户的 Safari 版本上验证。[MDN：WebSocket 客户端](https://developer.mozilla.org/en-US/docs/Web/API/WebSockets_API/Writing_WebSocket_client_applications)、[混合内容](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Mixed_content)

### 2.2 推荐 MVP：Mac App 内置本地网页

Mac 在同一端口提供静态网页与 WebSocket。iPhone 用系统相机扫描电视上的二维码，打开 Mac 提供的地址。用户不需要部署 Node、输入 GitHub 账户或在手机安装软件。

| 模式 | 页面与连接 | 成本／限制 | 本版定位 |
| --- | --- | --- | --- |
| Mac 本地网页 | 本地 HTTP + 同源 WS | 未加密，只适用于受信任家庭局域网；需验证 Safari | 推荐 MVP |
| Pages 控制页 | Pages HTTPS + Mac WSS | 需要证书信任、域名／地址解析与浏览器兼容方案 | 后续候选 |
| 线上页与中继 | HTTPS + 云端转发 | 新增服务器、认证、延迟与维护 | 范围外 |

本地页面示例：`http://实际Mac主机名.local:端口/`。示例不是可直接访问的链接，实际地址由 Mac 检测并展示。同源 HTTP + WS 避免 HTTPS 页面降级连接的问题，但不是加密方案。

GitHub Pages 可以用于介绍、安装指引、下载入口和不连接真实设备的交互演示。实际控制页跟随 Mac App 一起分发。若用户决定必须用 Pages 直接控制，应先完成 HTTPS/WSS 部署原型，再修改本基线。

## 3. 使用流程与 MVP 范围

### 3.1 日常流程

1. Mac 已登录、已解锁、保持唤醒，菜单栏接收端运行。
2. 打开电视并选择 Mac 的 HDMI 输入。
3. 打开 iPhone 上的本地网页书签或主屏幕入口。
4. 页面恢复认证与连接，连接成功后启用触控区。
5. 打开视频应用／网站，浏览、筛选、选择视频。
6. 搜索时先点击 Mac 搜索框，再用指针点击 Mac 屏幕键盘。
7. 观看时可锁手机；再次回到页面后自动尝试恢复连接。

### 3.2 功能清单

| 编号 | 功能 | 必须达到的结果 |
| --- | --- | --- |
| F-01 | 页面入口 | Mac 显示实际访问地址和二维码，手机可打开 |
| F-02 | 配对与授权 | 主动开启配对窗口，认证完成前不执行输入，支持撤销 |
| F-03 | 重连 | 页面刷新、返回前台后可恢复，连接前禁用触控 |
| F-04 | 单指滑动 | 相对移动指针，落点不映射绝对位置 |
| F-05 | 单指轻点、双击 | 左键单击和正确双击，无额外第三次点击 |
| F-06 | 双指轻点 | 一次右键点击 |
| F-07 | 双指滑动 | 横向、纵向、斜向连续滚动，抬手停止 |
| F-08 | Mac 管理 | 菜单栏状态、配对、地址、断开、移除设备、设置、退出 |
| F-09 | 登录启动 | 使用系统支持方式注册并展示真实状态 |
| F-10 | 权限指引 | 辅助功能、局域网、屏幕键盘和睡眠说明 |
| F-11 | 手感设置 | 指针速度、滚动速度、自然滚动、恢复默认 |

### 3.3 不做

- 手机键盘、文字／剪贴板同步、陀螺仪、键鼠模式切换。
- 长按或双击拖拽、三指手势、缩放、旋转、Force Touch、惯性滚动。
- 虚拟 HID、驱动、私有 API、真正 Magic Trackpad 设备模拟。
- 屏幕镜像、录屏、读取其他应用输入框、自动弹出辅助功能键盘。
- 自动调整系统睡眠、锁屏或登录设置；开机解锁、FileVault、网络唤醒。
- 专用播放／音量／快进按钮、电视电源、HDMI-CEC。
- 云服务、跨公网、蓝牙、账户、广告、遥测、自动更新。
- iPhone 原生 App、IPA 分发或 App Store 发布。

拖动播放进度条不在保证范围内；点击能否跳转由视频应用决定，不能为个别应用悄悄扩大范围。

## 4. 界面与手势规范

### 4.1 手机页面

- 竖屏优先、简体中文；左上显示 Mac 名称与连接状态，右上设置，主体为大触控区。
- 不展示远程画面或第二个鼠标指针；首用提示“单指移动与点击，双指右键与滚动”。
- 未配对、重连、Mac 无权限等状态禁用触控；提供明确重试和配对指引。
- 设置包括速度、自然滚动、断开、忘记此 Mac；手动断开后本次不立即自动连回。
- 字体、图标、脚本全部随 App 打包，不依赖 CDN；外网断开不影响控制页重新加载。
- 处理浏览器动态工具栏和 safe area；屏幕旋转时取消当前手势。
- 普通 Safari 页面是必验入口；主屏幕入口作为增强体验，单独验证存储与恢复行为。[Apple：添加到主屏幕](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)

### 4.2 浏览器输入

使用 Pointer Events 跟踪每个触点，处理 `pointercancel`、捕获丢失、导航、页面隐藏。触控区使用 `touch-action: none`，防止滚动网页、双击缩放、文字选择和长按菜单；设置区保持正常浏览能力。系统边缘手势不能保证被网页覆盖，保留操作安全区域。[MDN：Pointer Events](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events)

不依赖网页相机或 Service Worker；扫码使用系统相机。HTTP 页面不承诺完整离线 PWA 能力。界面按钮与触控区不能同时消费一次触摸，Safari 合成 click 不得导致重复点击。

### 4.3 移动与点击

- 移动使用 CSS 像素增量；协议右、下为正，Mac 转换为显示器逻辑坐标。
- Mac 从当前真实指针位置累加，处理边界与小数余量，不把电视物理像素直接当逻辑点。
- 首版采用可调倍率，只在一个层次应用，不叠加复杂自定义加速度。
- 轻点满足时长和位移阈值，容忍少量手抖；移动结束不能再点击。
- 第一遍轻点立即执行一次单击；第二遍符合双击条件时作为第二次点击，并设置正确点击计数。
- 禁止第一遍单击后再额外执行完整双击；移动、多指、超时、取消均重置连续点击。
- Mac 读取系统双击间隔并在就绪时同步给页面。[Apple：双击间隔](https://developer.apple.com/documentation/appkit/nsevent/doubleclickinterval)、[点击计数](https://developer.apple.com/documentation/coregraphics/cgeventfield/mouseeventclickstate)

### 4.4 双指与互斥

- 双指短暂触摸且位移未超阈值，抬起产生一次右键。
- 双指中心位移超过阈值后锁定滚动，允许横纵同时输出，结束不产生右键。
- 自然滚动默认开启：内容随手指移动；关闭反向，以实际内容运动验收，防止两端重复反转。
- 使用像素级连续滚动，首版不产生抬手后惯性；若使用阶段字段，开始／更新／结束／取消必须闭合。
- 第二指加入取消单指候选；双指结束只剩一指时，等待全部抬起才重新识别。
- 三指、系统接管、旋转、切后台、断线均取消手势，恢复后必须重新落指。
- 识别状态机、阈值、双指落下容差集中管理，初值经真机调校后冻结。

## 5. 技术架构

一个源码仓库，一个 macOS target，一个 TypeScript 网页工程。网页产出静态文件，构建时自动嵌入 Mac App bundle；最终用户不需安装 Node。

| 模块 | 所属 | 职责 |
| --- | --- | --- |
| GestureEngine / TrackpadSurface | Web | 触点、状态机、动作意图 |
| ConnectionClient / Settings | Web | 同源 WS、连接状态、本地手感设置 |
| MenuBarUI / SetupFlow | Mac | 状态、配对、地址、权限、登录启动 |
| HTTPServer / WebSocketServer | Mac | 提供资源、配对接口、控制连接 |
| SessionManager / CredentialStore | Mac | 凭据、认证、撤销、单会话、超时 |
| MouseEventExecutor | Mac | 唯一可生成系统输入的模块 |
| ProtocolSpec | 共享定义 | JSON Schema、版本和两端通用测试样例 |

Mac 使用 SwiftUI/AppKit、Core Graphics、ServiceManagement。HTTP/WS 使用 SwiftNIO 2.102.0 的编解码和分片聚合；依赖由 Package.resolved 锁定。工程使用 SwiftPM 和脚本打包 .app，构建需要 Swift 6.2+。网页使用 TypeScript + 普通 DOM，无运行时框架。

监听直接运行在菜单栏 App 中，无需额外 LaunchDaemon、root 进程、数据库或忙循环。`SMAppService.mainApp` 支持登录启动；不等于登录前控制。[Apple：登录启动](https://developer.apple.com/documentation/servicemanagement/smappservice/register())

输入使用公开 `CGEvent`。所有请求经过认证、会话、权限和参数校验后才能进入执行器。[Apple：CGEvent](https://developer.apple.com/documentation/coregraphics/cgevent)

## 6. 地址、配对与安全边界

### 6.1 地址与浏览器身份

- 普通网页没有与原生 NWBrowser 等价的通用 Bonjour 设备枚举能力；通过扫码／地址访问，不扫描局域网。
- Mac 默认显示选定私有 IPv4 与固定端口，实际 `.local` 主机名作为可选入口；必须真机验证解析，不凭空假定名称可用。
- 端口冲突明确提示；地址改变刷新二维码。手机的 localhost 指手机，不是 Mac。
- 协议、主机名、端口决定 origin；切换 IP、名称或端口可能导致凭据与设置隔离，应提示重新配对。
- 浏览器 Cookie 代表浏览器安装状态，不是不可变手机身份；无痕、清除数据、主屏幕存储隔离可能需重配。

### 6.2 配对方案草案

1. 用户在 Mac 主动开启配对，默认有效 5 分钟。
2. Mac 用系统安全随机数生成一次性高熵令牌，建议 256 bit。
3. 二维码包含本地页面地址，令牌放 fragment：`http://主机:端口/#pair=…`。
4. 页面读取 fragment 后立即清除地址中的秘密，再向同源配对接口提交。
5. Mac 检查时效与状态，原子消费一次性令牌，创建独立浏览器凭据。
6. 用 `HttpOnly; SameSite=Strict` Cookie 保存，建议初始有效期 30 天；Mac 保存可撤销记录。
7. 控制连接核对 Cookie、精确 Origin 与单控制者状态，返回新 sessionID 后允许操作。

fragment 减少秘密进入 URL 请求日志，但 HTTP 请求仍未加密；不得称为安全传输。HTTP 不能依靠 Secure Cookie，若迁移 HTTPS 必须同步升级 Cookie 策略。长期秘密不进入网页 localStorage、日志或源码。

### 6.3 必须实现的访问限制

- 仅监听本机和指定受信任局域网接口，避免公开接口／端口映射；清楚显示实际监听地址。
- HTTP Host、WebSocket Origin 使用精确允许列表，不从未经验证的客户端 Host 动态生成白名单。
- 配对 API 限同源，关闭宽泛 CORS；跨站请求、DNS rebinding、无效身份必须拒绝。
- 限制消息大小、未认证连接、认证时限和失败尝试；Origin 检查不能代替认证。
- 一台 Mac 同时只允许一个活动控制会话；第二台手机或第二标签页返回 busy，不静默抢占。
- 移除配对立即断开且旧 Cookie 无效；主机主动断开通知页面停止本轮自动重试。
- 页面没有执行离线回调也不应永久占用会话，服务端用心跳超时释放。

### 6.4 未加密本地模式的适用条件

HTTP/WS 仅适合受信任家庭局域网。页面、凭据与指令没有 TLS 保护，不能防御同网链路上的窃听和篡改，不适合公共 Wi-Fi 或开放公网。Host／Origin／令牌不能消除这一风险，社区安装说明必须明示。

如需更强保护，应先实现浏览器可信的 HTTPS/WSS 部署。不能仅给消息加密，就宣称解决了 HTTP 网页本身可被替换的问题。用户尚未明确选择未加密路线，M0 冻结前应确认此部署取舍；页面与输入原型可独立推进。

## 7. 协议 v1 与输入一致性

WebSocket 一条消息对应一个 UTF-8 JSON 对象，不沿用原生 TCP 的额外长度前缀。库负责分帧重组，应用解码后单消息建议上限 16 KiB。

| 类型 | 方向 | 内容 |
| --- | --- | --- |
| hello / ready | 双向 | 版本协商、会话、双击时间配置 |
| move | Web → Mac | dx、dy，CSS 像素，右／下为正 |
| click | Web → Mac | 左／右及连续点击信息；Mac 成对生成 down/up |
| scroll | Web → Mac | dx、dy、开始／更新／结束／取消 |
| ping / pong | 双向 | 应用层心跳与 RTT |
| status / error | Mac → Web | 权限、忙碌、版本与其他状态 |
| disconnect | 双向 | 结束和原因 |

- 认证后输入有版本、sessionID、单调递增 seq；重连新建会话，不重放旧消息。
- 拒绝未知类型、旧会话、非法长度、非有限数字和超限位移；不提供任意系统命令、文字或键盘入口。
- 输出目标约 60 次／秒，可按浏览器帧回调合并；合并相对移动必须累加增量。
- 点击前处理此前移动；滚动结束／取消不能丢失，Mac 串行执行。
- 每次 click 原子地安排完整 down/up；首版不允许长期按住。
- 监测 WebSocket bufferedAmount 和服务端背压，持续拥塞取消手势并重连，禁止囤积旧操作后播放。
- 初始心跳可每 2 秒一次，约 6 秒无响应断线；浏览器后台定时器冻结由服务端超时兜底。
- RTT 用同一端时钟测；不能直接相减两台设备的时间戳宣称单向延迟。

## 8. 生命周期、权限与运行状态

页面状态：`加载 → 未配对／认证 → 连接中 → 已连接 → 暂停／重连`。

处理 visibilitychange、pagehide、pageshow、网络变化；隐藏时停止采集与高速重试。回前台检查身份、连接与主机就绪状态，清空手势后恢复。主动断开本次不立即重连；自动重试可按 0、1、2、4 秒，再上限 10 秒退避并加抖动。

| 状况 | 预期体验 |
| --- | --- |
| 无法打开网页 | 检查 Mac 服务、地址和网络，不把一切归因于权限 |
| 未配对／凭据撤销 | 引导在 Mac 开启配对并扫码 |
| 重连中 | 显示状态，禁用触控，不缓存待执行手势 |
| Mac 权限缺失 | 明确提示到 Mac 授权；连接可保留以同步状态，输入禁用 |
| 被占用 | 返回 busy，不抢占 |
| 睡眠／关机 | 显示不可达，不承诺唤醒 |

Mac 首次引导辅助功能授权；运行中权限失效应停止输入。新版 macOS 也有局域网隐私机制，按实际系统验证。[Apple：局域网隐私](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)

不请求录屏、读取真实键盘、完全磁盘访问或管理员权限。Mac 默认普通非 App Sandbox 应用，签名分发使用 Hardened Runtime，两者不能混淆。

屏幕键盘由用户手动开启和摆放；并非点击输入框自动弹出。[Apple：辅助功能键盘](https://support.apple.com/zh-cn/guide/mac-help/mchlc74c1c9f/26/mac/26)

电视关闭、Mac 睡眠、锁屏是不同状态。正式范围是 Mac 已登录、已解锁、保持唤醒；提供“显示器关闭时防止自动睡眠”说明，不自动修改设置。保持运行仍有空闲功耗；初装与重启首次登录保留实体键鼠等现有方式。[Apple：睡眠设置](https://support.apple.com/zh-cn/guide/mac-help/-mchle41a6ccd/mac)

## 11. 单仓库开源、安装与维护

Mac 源码、网页源码、协议与文档在同一仓库维护。网页是产品的一部分，应同时开源，不能只公开 Mac 壳程序而遗漏控制页源码。用户安装 Mac App 后，手机通过局域网访问它提供的网页；社区成员无需单独托管前端、部署服务器或安装 iPhone App。

当前仓库已实现 0.1.0 开发预览并生成本机签名 App，尚未公开发布或完成真机验收。构建和安装步骤见 installation.md，不能将本机自动测试写成 Safari 或客厅实测通过。

- iPhone：Safari 打开即可，不需 IPA、开发者模式或手机签名续期；主屏幕入口以真机验证为准。
- Mac 自用：Xcode 构建，安装到稳定路径，配置辅助功能与登录启动。
- Mac 社区二进制：推荐 Developer ID 签名、Hardened Runtime、公证，准备 zip/dmg；不要求上 Mac App Store，但相应证书与公证需要开发者计划。[Apple：Developer ID](https://developer.apple.com/developer-id/)、[公证](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)
- 源码分享：提供可复现构建、许可与签名说明；项目采用 MIT 许可证；第三方依赖仍需遵循各自许可。
- GitHub Pages：可发布介绍与无真实连接的演示，实际控制页由每个用户自己的 Mac 提供；准备内容不代表已获公开发布授权。
- 手动更新 Mac App，同步更新网页；版本不兼容要求刷新，不能静默误解析命令。
- 默认无遥测，日志由用户主动导出，脱敏网络标识和秘密。
- 无云服务器费用；主要成本为开发、真机测试和 Mac 分发维护。个人本地构建与面向社区提供低摩擦安装包的成本不同。
