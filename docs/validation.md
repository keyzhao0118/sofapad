## 0.8.x 变更与复验

发布后清理了收尾瑕疵，并按用户要求简化启动与传输方式：

- Mac 版本号文案不再包含已移除的“遥控”，改为读取 `Info.plist`，与打包版本不会漂移。
- `scripts/test.sh` 在 `Web/node_modules` 缺失时自动执行 `pnpm install --dir Web --frozen-lockfile`，与构建脚本一致。
- `scripts/build.sh`、`scripts/test.sh` 支持 `SWIFT_BUILD_FLAGS`／`SWIFT_TEST_FLAGS` 参数透传；外层已启用 sandbox-exec 的受限环境（嵌套沙箱或部分 CI）用 `SWIFT_TEST_FLAGS=--disable-sandbox bash scripts/test.sh`，普通本机会话不需要该参数。
- 开机自启修复：登录启动时 App 常早于网络就绪，届时没有任何可用地址，服务不会开启且没有重试；现在 `refresh()` 在地址出现时自动开启、地址或主机名变化后自动按新地址重启，用户主动停止则保持关闭（`ServiceLaunchPolicy` + 单元测试）。
- 安装包落点修复：安装包曾因 `pkgbuild` 的 bundle 重定位（PackageInfo 中的 `<relocate>`）而全盘查找同标识 App 并就地更新，导致双击 pkg 时覆盖 `build/SofaPad.app` 而不是装入 `/Applications`；打包脚本现展开安装包、移除该元素后重新封装，并核验新包 PackageInfo 不再包含 `<relocate>`。
- 固定地址：菜单栏同时显示本机 `.local` 名与当前 IP 两个地址，Host 白名单接受这两者、其他主机名 403；不再提供“复制地址”。`NetworkAddress` 重新读取本地主机名，主机名或地址变化时停止服务并提示。
- 简化连接方式：去掉配对、二维码、Cookie 与 HTTPS，App 启动即自动开启服务，同网段任意设备打开菜单栏地址即可控制；只保留 Host／Origin 精确校验、同源要求、单控制者与协议限额。删除 swift-nio-ssl 依赖、凭据存储、证书菜单与相关测试（Swift 24→19 项、集成 26→11 项），并重新生成安装包。
- 启动时若尚无辅助功能权限，主动调用系统授权提示；授权本身仍只能由用户在系统设置完成。本地网络权限排障入口不再出现在界面：服务端只接受传入连接，按 macOS 规则不需要该权限。
- Mac 界面收进菜单栏：状态、访问地址与复制、开启／停止、断开、辅助功能权限、登录启动与退出全部在菜单里；没有设置窗口，也没有配对窗口。App 增加正式图标（`MacApp/AppIcon.icns`，由 `scripts/make-icon.sh` 生成），并随构建打入包内。
- 语音听写改为“停顿即定稿”：识别中的文字以灰色留在输入框不发送，停顿 1.2 秒或结束听写时把已定稿部分作为 `edit` 键入 Mac 并上浮，输入框清空；识别引擎事后改词只重写尚未发送的尾部，因此 Mac 上不会出现删了重打的抖动。按词形区分听写与拼音预编辑（纯拉丁字母仍留在手机）。
- 输入体验收尾：输入模式改为覆盖在触控板上的顶部下拉面板（不再切换页面），输入框只有一行高，已发送字符先在行内停留约 0.5 秒再向上飘出淡出；点击面板外、键盘完成键或切换按钮都收起面板回到触控板，收起的那一下点击不产生鼠标操作，切后台／锁屏不收起；Mac App 未声明 `enter` 能力时同步提示会注明需要更新 App。
- 安装清理：删除 23 个构建备份目录与 6 个旧版本 zip（build 从 331MB 降到 84MB），Spotlight 中 `SofaPad.app` 只剩 `/Applications/SofaPad.app` 与 `build/SofaPad.app`；`build/.metadata_never_index` 已加入构建脚本，后续产物不再被索引。最新版已用 `ditto` 安装到 `/Applications`，签名校验通过、版本 0.8.0、图标完整。
- 打包与图标：新增 `scripts/package.sh` 生成本机 `.pkg`／`.zip`（可选 `.dmg`）与 `scripts/make-icon.sh` 生成 `MacApp/AppIcon.icns`。本机验证 `.pkg` 解包后 payload 为 `Applications/SofaPad.app`、签名有效、图标与网页资源完整、版本号一致；DMG 在受限环境（无磁盘映像权限）未生成，脚本改为提示并保留其余产物。
- 按“少露技术细节、开箱即用”再收敛一轮：移除主机名开关与 `.local` Host 支持（Host 白名单只保留绑定的 IP），单一网络地址时不再出现地址选择，界面按钮与提示改为用户语言，开启失败只提示检查网络而不再列出端口等细节；文档同步删除主机名相关说明。
- 修正输入法删除误判：删除是否发往 Mac 改为按“按键前”的状态判定（keydown／beforeinput 快照），组合期间的退格只缩小候选串，组合结束后 400 ms 内的收尾退格同样不发往 Mac；只有框本来就空时的删除键才发送退格。
- 输入模式新增“穿堂”式实时同步：协议 v2 增加 `edit`（先退格 `delete` 次再键入 `text`，delete ≤1024、text ≤4096 UTF-8 字节）与固定 `enter`（真正的 kVK_Return 按下／抬起，由目标应用决定换行／确认／提交），ready 以 `capabilities: ["backspace","edit","enter"]` 声明；已提交字符立即离开手机输入框、键入 Mac 并在上方飘出淡出，删除与回车分别显示 ⌫／↵ 且同样即时发送，空框删除键靠零宽哨兵识别，网页按 128 次退格／512 字节分片，只发送 IME 提交后的文本，撤销不重放，断线时输入框只读且重连从空框开始；未声明该能力的旧主机继续使用整段粘贴与退格按钮。

复验结果：网页 52、Swift 20、HTTP/WS 回环 11 全部通过；release App 重新构建并通过 `codesign --verify --deep --strict`，本机开发包 `build/SofaPad-0.8.2-macos-arm64.zip` 同步刷新，解包后签名校验有效。桌面 Chromium 回归本轮已复跑：用本机 Chrome 与临时安装的 `playwright-core`（`PLAYWRIGHT_MODULE`）执行 `Tests/Integration/browser_test.mjs` 并通过，含新的实时同步断言；仍不代表 iPhone Safari 结果。

## 0.9.x 变更与复验

- 多控制者（0.9.0）：删除会话级 busy 与“第二个连接只能排队”的旧行为。服务端 `ControlState` 改为持有会话表（id、客户端标签、权限校验、断线回调），每个连接独立会话与序号，输入仍在同一把锁与同一个执行器内串行执行；同一时刻以先开始的手势为准，其他会话的移动／点击／滚动被忽略直到该手势结束，只有持有指针的那一方断开时才释放按住的键。菜单栏显示控制者数量，可“断开当前控制者”或“断开全部控制者”；网页端删除 busy 状态与相应文案，`/api/status` 用控制者数量取代“是否被占用”。单元测试改为并行会话用例，集成测试新增两台设备各自 ping 互不影响与重连，Chromium 回归新增第二个标签页同时控制且第一个不受影响、关闭第二个后第一个仍连接的断言。
- 打包去残留（0.9.1）：发现 App 内夹带 `swift-nio-ssl_NIOSSL.bundle`。`swift-nio-ssl` 早在 0.8.0 就从依赖里删掉了，但 `.build` 中遗留的资源包会被 `scripts/build.sh` 的 `*.bundle` 循环原样拷进 App。现在只拷当前依赖（`swift-nio`／`swift-atomics`／`swift-collections`／`swift-system`）的资源包，其余跳过并提示；遗留的 `.build/debug`／`.build/release` 资源包与 `.build/checkouts/swift-nio-ssl` 已清除，重建后的 App 只含 `swift-nio_NIOPosix.bundle`。

- 侧边滚动可达性（0.9.2）：真实使用反馈“侧边的滚动区域经常不生效，双指滚动正常”。用 Chromium 触控事件逐像素扫描复现：滚动只在最外侧 28 px 窄条内生效（x=27 滚动、x=28 起变成移动指针），而渐隐提示在视觉上覆盖 76 px，拇指按提示落点经常落在窄条外，于是“时好时坏”。现在窄条外到 76 px 之间新增判定带：首个采样方向明确（纵向或横向达 2.5 倍）就地判定，否则等累计 14 px 再按多数方向决定，避免起手几像素的抖动把纵向滑动误判成指针移动；滚动时对应一侧渐隐标记加深。带宽改由 `--edge-strip`／`--edge-band` 提供，手势代码读取同一份数值。新增 7 项网页单元测试（判定带、抖动、短距离不猜测、横滑与轻点保持原行为、混区取消清理高亮）与 Chromium 回归断言（判定带滚动与高亮、带外仍是移动指针、带内横滑仍是移动指针、右侧判定带）。

- 手感默认值与滑杆量程（0.9.3）：按用户实测把默认值改为指针 1.5×、滚动 0.3×。滑块改为 0–100 行程、中点即默认值、两半各按对数刻度（`Web/src/settings-range.ts`），范围扩到 0.2–5.0 与 0.05–5.0，两端都比原来的 0.3–4.0 宽；历史存档越界时夹紧而不是丢弃。新增 5 项量程单元测试（中点、两端、单调与往返、夹紧、文案），Chromium 回归改为断言默认值落在滑杆中点、改速后按读回的实际倍率校验位移。
- 轻点后拖动误判（0.9.3）：用户反馈连续滑动鼠标时会把指针移动变成点按后拖动。用 Chromium 触控脚本复现：不足 8 px、240 ms 内的轻微触碰按规则是单击，此前紧随其后的滑动会命中"单击后按住拖动"。现在该手势要求第二次按下先静置 150 ms（`thresholds.dragHoldMs`）再滑动，起手立即移动的手势按指针移动处理；新增 3 项手势单元测试（连续滑动不再变拖动、静置后仍拖动、起手即滑不拖动），Chromium 回归的轻点后拖动用例改为先静置。
- 静态资源 404（0.9.3）：新增 `settings-range.ts` 后页面停在"正在连接 Mac…"，原因是 Mac 端 `WebFiles` 写死了六个文件名，新模块被回 404。改为按构建目录提供 .html／.css／.js，并强制要求 index.html、style.css、app.js 存在；回环测试新增"逐个请求 Web/dist 中的每个资源"，网页资源 404 这类问题以后会在自动化里直接暴露。

复验结果见上表：网页 67、Swift 20、HTTP/WS 回环 12 全部通过，桌面 Chromium 回归通过（含两个标签页同时控制、判定带、默认值中点与轻点后拖动用例）。
